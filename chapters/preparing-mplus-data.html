10  Preparing and Reading Mplus Files

Mplus data must be in space-delimited format with no header (e.g., no variable names).

This process can be automated using the MplusAutomation package (Hallquist & Wiley, 2018), which exports a properly formatted .dat file and generates a starter .inp file with the variable names, order, and missing-value code already filled in – removing the need to manually retype variable lists (a common source of misalignment errors between R/SPSS and Mplus).

NoteWhat is an .inp file?

An .inp file is a plain-text Mplus input file – it’s the script that tells Mplus what data to read, how to treat each variable, and what model to run. Every Mplus analysis starts from one. It’s organised into commands like:

  • DATA: – where to find the .dat file

  • VARIABLE: – variable names, missing-value codes, which variables are categorical, which to use in the model, etc.

  • MODEL: – the actual model specification (e.g., factor structure, regressions, paths)

  • OUTPUT: – what results to print (standardised estimates, modification indices, etc.)

The code below only fills in the DATA: and VARIABLE: sections automatically, since those depend on the structure of your dataset.

install.packages("MplusAutomation")
library(MplusAutomation)

gender_ownership_t2 %>%
  mutate(
    GENDER = case_when(
      GENID == "man" ~ 1,
      GENID == "woman" ~ 2,
      TRUE ~ NA_real_
    ),
    OPP = case_when(
      opinion_group == "supporter" ~ 1,
      opinion_group == "opponent" ~ 2,
      TRUE ~ NA_real_
    )
  ) %>%
  dplyr::select(COGE1, COGE2, COGE3,
                TTHR3, TTHR4,
                TEM12, TEM13,
                OPP,
                TCA3, TCA4, TCA5, TCA7, TCA9,
                TFA3, TFA4, TFA5, TFA7, TFA9,
                GENST, AGE, EDUC, CONS, GENDER) %>%
  prepareMplusData(filename = "ownership_s2.dat", inpfile = TRUE)

What this is doing:

  • mutate() recodes to factor variables into numeric form, since Mplus requires all variables to be numeric. GENID (“man”, “woman”, “non-binary person”, “other gender diverse person”) is recoded into GENDER (1/2 - only controlling for binary gender in the models as there are insufficient cases of gender diverse folk in the data), and opinion_group (“supporter”/“opponent”) is recoded into OPP (1/2) because the models I was running were predicting opponent (vs supporter) self-categorisation. Any value that doesn’t match the specified condition becomes NA.

  • dplyr::select() retains only the variables needed for the Mplus model, in a fixed order. The column order matters here, since Mplus reads data by position rather than by name – the order in select() determines the order Mplus expects in NAMES ARE

  • prepareMplusData() writes two files here:

    • ownership_s2.dat – the space-delimited data file, with all NA values automatically recoded to -99.

    • ownership_s2.inp – a template Mplus input file with the DATA: and VARIABLE: sections pre-filled, including NAMES ARE (variable list, correctly ordered) and MISSING ARE ALL (-99);

10.2 Running models in R

Once your .inp file is complete (data/variable sections generated by prepareMplusData(), plus your MODEL: and OUTPUT: sections added by hand), you can actually run it directly from R using runModels().

WarningRequirements

Running the Mplus models in R still requires Mplus to be installed locally, as runModels() actually calls Mplus behind the scenes.

runModels("ownership_s2.inp")

By default, this looks for ownership_s2.inp in the working directory and produces ownership_s2.out alongside it, exactly as if you’d opened and run the file in the Mplus GUI. If you have several related .inp files in a folder (e.g., a set of measurement invariance models), you can run them all in one call.

runModels("path/to/folder", recursive = TRUE)

  • Note: recursive = TRUE also parses .inp files in subdirectories, which is useful for batches of nested model comparisons.

  • Also note: I do not have Mplus locally installed, so I haven’t tried this myself. See https://michaelhallquist.github.io/MplusAutomation/index.html for more guides.

10.3 Reading model output into R

If you have been sent an .out file, or you ran your models in Mplus on another device, you can still read them into R and parse out the model results from there. This is done using the readModels() function, which parses one or more .out files and returns their contents as structured R objects (fit statistics, parameter estimates, modification indices, etc.). To reiterate, this works on any .out file, whether it was produced by runModels() or run independently through the Mplus program, so this step does not require Mplus to be installed locally.

results <- readModels("ownership_s2.out")  # View fit statistics results$summaries  # View parameter estimates results$parameters$unstandardized

Useful sub-elements of the returned object include:

  • summaries – fit indices (CFI, TLI, RMSEA, chi-square, etc.)

  • parameters – unstandardised and standardised estimates, standard errors, p-values

  • mod_indices – modification indices

  • class_counts – latent class counts/proportions (for mixture models)

  • indirect – indirect effect estimates (for mediation models)

If you’re parsing many output files at once (e.g., a batch of related models), point readModels() at the containing folder with all .out files.

all_results <- readModels("path/to/folder", recursive = TRUE)

10.4 Full workflow

You can also write your .inp file in R as well. I choose to do this because I prefer to work in R as much as possible. As such, I like to keep a transparent record of the model building process in R, as well as read my Mplus output back into R so that everything I need is in my R project for when I upload it all to OSF.

10.4.1 Step 1: Prepare the data and retain only the variables required across your analyses

ownership_s2 <- gender_ownership_t2 %>%
  mutate(
    GENDER = case_when(
      GENID == "man" ~ 1,
      GENID == "woman" ~ 2,
      TRUE ~ NA_real_
    ),
    OPP = case_when(
      opinion_group == "supporter" ~ 1,
      opinion_group == "opponent" ~ 2,
      TRUE ~ NA_real_
    )
  ) %>%
  dplyr::select(COGE1, COGE2, COGE3,
                TTHR3, TTHR4,
                TEM12, OPP, PREJ,
                TCA3, TCA4, TCA5, TCA7, TCA9,
                TFA3, TFA4, TFA5, TFA7, TFA9,
                GENST, AGE, EDUC, CONS, GENDER)

What this is doing:

  • This is the same as above, except rather than specifying -99 as missing data, I am letting the MplusAutomation package use it’s automatic process of turning all NA values to . – this is a readable missing value code in Mplus.

10.4.2 Step 2: Define the model

The model itself is defined using mplusObject().

m1a <- mplusObject(
  TITLE = "M1a - Predicting opponent self-categorisation (categorical);",

  VARIABLE = "
    USEVARIABLES = TEM12 OPP COGE1 COGE2 COGE3 SYMB;
    CATEGORICAL = OPP;",

  DEFINE = "
    SYMB = (TTHR3 + TTHR4) / 2;",

  ANALYSIS = "
    ESTIMATOR = WLSMV;",

  MODEL = "
    CPO BY COGE1* COGE2 COGE3;
    CPO@1;
    SYMB ON CPO;
    TEM12 ON CPO;
    SYMB WITH TEM12;
    OPP ON CPO SYMB TEM12;",

  MODELINDIRECT = "
    OPP IND SYMB CPO;
    OPP IND TEM12 CPO;
    OPP IND CPO;",

  OUTPUT = "
    STDYX;
    CINTERVAL;
    SAMPSTAT;
    TECH1;",

  rdata = ownership_s2
)

What this is doing:

  • This is filling in all the missing sections of the .inp file that were excluded in the first step. Write it as you would typically write an Mplus .inp file.

10.4.3 Step 3: Write the .dat and .inp files

Once the model object has been created, mplusModeler() generates both the Mplus data file and the Mplus input file.

m1a_fit <- mplusModeler(
  m1a,
  dataout = "mplus/ownership_s2.dat",
  modelout = "mplus/m1a.inp",
  run = 0L,
  hashfilename = FALSE,
  writeData = "always"
)

What this is doing:

  • This creates two files:

    • ownership_s2.dat, containing the data in Mplus format

    • m1a.inp, containing the complete Mplus syntax generated from mplusObject()

  • hashfilename = FALSE means that earlier versions of the files are overwritten if you run the code multiple times. If you turn this feature on, it saves a new version of the file each time with a unique identifier.

  • run = 0L means that the input file is generated but the model is not run. If you have a locally stored copy of Mplus on your device, you can change this to 1L and it will save both the .dat and .inp files as well as actually run the models using Mplus integration.

10.4.4 Step 4: Checking syntax

Before running the model, it can be useful to check the generated syntax.

parseMplus(readLines("mplus/m1a.inp"))

What this is doing:

  • This identifies common syntax problems before Mplus attempts to run the model.

  • However, it may tell you that you’re missing semicolons at the end of lines but does not know when you have split your syntax across multiple lines to get around Mplus’s per-line character limit. So, better to open the .inp file in a plain text reader to see if that really is a problem or not.

  • If you did need to add a semicolon for whatever reason, you can run that same code again with add = TRUE tacked on at the end of the function, and this will ensure there is a semicolon at the end of every line. But if you use this automatically, it will literally do this for every line even if your syntax is split across multiple, which will then cause the model to produce errors.

10.4.5 Step 5: Reading model output into R

Say I had run multiple models in Mplus. I could read all of the corresponding .out files separately into R like so.

results_m1a <- readModels("mplus/m1a.out")
results_m1b <- readModels("mplus/m1b.out")
results_m2a <- readModels("mplus/m2a.out")
results_m2b <- readModels("mplus/m2b.out")

And then get the summary statistics, and inspect the model outputs.

# View fit statistics
results_m1a$summaries
results_m1b$summaries
results_m2a$summaries
results_m2b$summaries

# View standardised estimates
results_m1a$parameters$stdyx.standardized
results_m1b$parameters$stdyx.standardized
results_m2a$parameters$stdyx.standardized
results_m2b$parameters$stdyx.standardized

You can also read them into several larger overview objects. For example:

all_results <- readModels("mplus/", recursive = TRUE)

names(all_results) <- c("M1a", "M1b", "M2a", "M2b") # Rename to something meaningful rather than automatic file path name
all_results

# Combine the summaries from all models into one dataframe
fit <- bind_rows(
  M1a = all_results$M1a$summaries,
  M1b = all_results$M1b$summaries,
  M2a = all_results$M2a$summaries,
  M2b = all_results$M2b$summaries,
  .id = "model"
) %>%
  dplyr::select(-AnalysisType, -DataType, -Title, -NGroups, -NDependentVars, -NIndependentVars, -NContinuousLatentVars, -ChiSqBaseline_Value, -ChiSqBaseline_DF, -ChiSqBaseline_PValue, -ChiSqM_ScalingCorrection, -LL, -LLCorrectionFactor, -UnrestrictedLL, -UnrestrictedLLCorrectionFactor, -ParametersWithAux, -AICC, -Filename)

What this is doing:

  • This is reading all models into one object and renaming the models to a short and more meaningful call name, so that if you were, for example, to run all_results$m1a$parameters$stdyx.standardized you would get the standardised estimates for Model 1a, and if you ran all_results$m1b$parameters$stdyx.standardized you’d get the same for Model 1b, and so on and so forth.
